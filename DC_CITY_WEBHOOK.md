# DC City (pay.dc.tj) — подключение колбэка для пополнения баланса RentHub

Статус: **ожидается от DC City.** Всё с нашей стороны готово и уже работает
в проде — нужен только сам колбэк.

---

## 1. Что нужно сделать

Зарегистрировать у себя (на стороне pay.dc.tj) отправку POST-запроса на наш
эндпоинт **каждый раз, когда платёж прошёл успешно (и, если возможно, когда
отклонён)**.

```
POST https://renthub.qobus.tj/api/v1/webhooks/pay-dc
Content-Type: application/json        (или application/x-www-form-urlencoded)
```

---

## 2. Секрет

Для подтверждения запроса используется общий ключ. Он уже сгенерирован у нас
и хранится в файле `.env` сервера RentHub под ключом `PAYDC_WEBHOOK_SECRET`.

**Мы передадим его отдельным защищённым каналом** (не письмом в открытом
виде). Куда его передать — договариваемся с вами.

Приём секрета с нашей стороны, любой из двух способов:

1. заголовок: `x-paydc-secret: <секрет>`
2. либо поле в теле запроса: `secret` / `token` / `key` / `sign` / `signature`

Запрос **без секрета или с неверным секретом получит `403`** и ничего не
зачислит.

---

## 3. Поля запроса

Тело принимается и как JSON, и как обычная форма (`key=value&...`).

| Назначение | Принимаемые имена (в порядке приоритета) | Наше значение |
|---|---|---|
| Референс платежа | `f3`, `reference`, `ref`, `invoice`, `invoice_id`, `order_id`, `OrderId`, `id` | **то, что пришло в параметре `f3`** ссылки |
| Сумма | `s`, `amount`, `Amount`, `sum`, `total`, `value` | сумма в таджикских сомони, напр. `75.00` |
| Статус (необяз.) | `status`, `state`, `result` | `ok`/`success`/`paid` — успех; `fail`/`declined`/`cancel`/`0` — отказ |

Отдельное поле секрета: `secret` / `token` / `key` / `sign` / `signature`
(или заголовок `x-paydc-secret`).

**Откуда берутся значения.** Наша ссылка на оплату выглядит так:

```
https://pay.dc.tj/?a=9762000220865843&f1=133&c=DANAT.TJ&s=75.00&f2=26&f3=D980716DC3A044519C502D8C
                       ^счёт            ^арт.  ^описание  ^сумма ^юзер ^референс
```

`f2` и `f3` — свободные поля, которые вы пропускаете насквозь. Вернуть нужно
именно **`f3`** (это референс) и **`s`** (это сумма).

---

## 4. Ответы, которые вернёт RentHub

| HTTP | `reason` / `detail` | Значение |
|---|---|---|
| `200` | `CREDITED` | зачислено |
| `200` | `ALREADY_PAID` | уже зачислено раньше (повтор), денег не добавлено |
| `200` | `DECLINED` | платёж отклонён, ничего не зачислено |
| `200` | `UNKNOWN_REFERENCE` | такого `f3` мы не выдавали |
| `200` | `AMOUNT_MISMATCH` | сумма не совпала; остаётся «ожидает оплаты», можно повторить с верной суммой |
| `403` | `BAD_SECRET` | неверный или отсутствующий секрет |
| `503` | `WEBHOOK_NOT_CONFIGURED` | у нас не задан секрет (мы ещё не получили его от вас) |

Повторные запросы безопасны: идемпотентность, **зачисление ровно один раз**.

---

## 5. Проверка (можно выполнить с любого сервера)

```bash
curl -i -X POST https://renthub.qobus.tj/api/v1/webhooks/pay-dc \
  -H 'Content-Type: application/json' \
  -d '{"secret":"<СЕКРЕТ>","f3":"ТЕСТОВЫЙ_REF_ИЗ_ВАШЕЙ_ВЫПИСКИ","s":"75.00"}'
```

Ожидаемо: `200` с `{"ok":true,"credited":...,"reason":"..."}`.

Без секрета — `403`, что подтвердит, что эндпоинт жив и закрыт.

---

## 6. Что работает уже сейчас (без вашего колбэка)

Пока колбэк не подключён, пополнение закрывается оператором вручную: платеж
сверяется по `f3` в выписке DC Wallet и подтверждается в интерфейсе RentHub.
Это тот же код зачисления, поэтому **когда вы подключите колбэк, ничего
менять не нужно** — он просто начнёт работать автоматически.

> артикул 133). Нужно настроить отправку уведомления о платеже на наш адрес:
>
> `POST https://renthub.qobus.tj/api/v1/webhooks/pay-dc`
>
> Тело — JSON или обычная форма, поля:
> `f3` — референс платежа (мы передаём его в параметре `f3` ссылки),
> `s` — сумма,
> `secret` — общий ключ (мы передадим отдельно), либо заголовок
> `x-paydc-secret`.
>
> Отправляйте на каждый успешный платёж. Спасибо!
